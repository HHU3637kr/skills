模板使用说明（复制后删除本节）

frontmatter 双轨等价（不允许缺字段）

原 YAML frontmatter 有两个作用：机器可读（检索、工具化提取）和人可读。两轨都要保留，缺一不可。原模板有几个字段，HTML 就要有几个对应的 <meta> / <link>；禁止因为"HTML 里看不见"就删字段。

原 frontmatter 字段必填机器可读人可读可选值 / 说明
title是<meta name="rk:title"><h1>Spec 标题
type是<meta name="rk:type">.rk-meta 类型plan
category是<meta name="rk:category">.rk-meta Spec 路径01-产品规划/02-技术设计/03-能力交付/04-系统改进/05-验证工程；必须按 spec-write 的分类决策顺序选择，不能默认写 03
（Spec 目录）是<meta name="rk:spec-dir">.rk-meta Specspec/<分类>/<YYYYMMDD-HHMM-中文任务描述>
（产出角色）是<meta name="rk:role">.rk-meta 角色spec-writer
status是<meta name="rk:status">.rk-meta 状态未确认/已确认/已归档
priority是<meta name="rk:priority">.rk-meta 优先级高/中/低
execution_mode是<meta name="rk:execution-mode">.rk-meta 执行模式v2.0 固定 single-agent
created是<meta name="rk:created">.rk-meta 创建YYYY-MM-DD
（本轮修订日期）是<meta name="rk:updated">.rk-meta 修订YYYY-MM-DD
（修订号）是<meta name="rk:revision">.rk-meta 修订 r{N}每次修改 +1
git_branch是<meta name="rk:git-branch">.rk-meta 分支ASCII 分支名，如 feat/spec-20260428-1430-user-auth，由 spec-start 创建
base_branch是<meta name="rk:base-branch">.rk-meta 分支（← 基准）通常 main
pr_url否<meta name="rk:pr-url">（未创建留空）.rk-meta PR（未创建写 —）GitHub PR URL，spec-end 写回
tags是<meta name="rk:tags">，逗号分隔不必显示至少含 spec 和 plan；不在正文堆 #tag
related否<link rel="rk-related">rk-links 列表项关联的其他 Spec
GitHub Flow 元数据

rk:git-branch / rk:base-branch 由 spec-start 通过 git-work 创建并传入。不要手写一个不存在的分支；如果项目不是 Git 仓库，写 none 并在「风险和依赖」说明原因。

双向关联（正向 + 反向都要）

Obsidian 双链的价值不只是跳转，而是反向可发现。只写单向 <a> 属于功能退化。做法：

  • 正向：<ul class="rk-links"> + <a href="..." data-rk-link="{类型}">，同时在 <head> 加 <link rel="rk-*">；
  • 反向：<ul class="rk-backlinks"> + <a href="..." data-rk-backlink="{类型}">；
  • 本报告引用 B 时，B 的 rk-backlinks 也要补一条；对侧尚未创建就标注（待创建），等对侧产出后补齐。

必需章节

writer/plan.html 必须包含：概述（背景/目标/范围）、需求分析、设计方案、执行模式、实现步骤、验收关注点、风险和依赖、关联产物（双向）。

v2.0 变更：移除测试计划章节

writer/plan.html 不再包含测试计划章节。测试计划由 spec-tester 用 spec-test 单独创建 tester/test-plan.html。

修订规范

报告每次修改都必须可追溯，规范以 html-report skill 为唯一权威源，写报告前先读一遍。要点：

  1. rk:revision 与报告头「修订」字段同步递增（r1 → r2），并更新 rk:updated；
  2. 「修订历史」表追加一行，写清改了什么、为什么：源于实质取舍就在「原因」列引用账本 Decision Log 编号（如「按 D-003（多实例部署需共享缓存）」），纯笔误/措辞/补充直接写清、不编造编号；决策过程正文留在 lead/team-context.md 的 Decision Log，不复制进报告；
  3. 正文永不静默改写——行内用 <del class="rk-del" data-rev="N"> / <ins class="rk-ins" data-rev="N">，整段用 <p class="rk-removed|rk-added" data-rev="N">，每个标记都带 data-rev；
  4. 重点用 rk-verdict（结论）、rk-cal key|warn|risk|ok（Callout）、rk-kpis（指标卡）承载；
  5. 禁止 <style>、行内 style= 和外部 CDN，样式只在 rk-report.css。
