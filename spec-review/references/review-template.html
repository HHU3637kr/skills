审查报告模板

类型 template 角色 spec-reviewer 骨架 A reviewer/review.html（新功能审查） 骨架 B reviewer/update-XXX-review.html（更新审查） 契约 html-report skill
用法

下面两个代码块各是一份完整可直接另存的 HTML 文档：整块复制（含 <!DOCTYPE> 到 </html>） 另存为 reviewer/review.html 或 reviewer/update-XXX-review.html，再逐个替换 {占位符}。 样式路径 ../../../../html-report/assets/ 按 reviewer/ 回到项目根的 4 层计算，项目实际层级不同需相应调整。

不允许功能退化

骨架里的 <meta name="rk:*"> 与 <link rel="rk-*"> 是原 YAML frontmatter 的机器可读等价物， .rk-meta 是同字段的人可读镜像，两轨缺一不可。关联产物分「本报告引用」（rk-links）与 「引用本报告」（rk-backlinks）两向，等价 Obsidian 双链的正向跳转 + 反向可发现。禁止删字段，禁止只写单向链接。

元信息字段说明

每个字段都有机器可读（<meta> / <link>）与人可读（.rk-meta / 关联产物列表）两轨，缺一不可。 原模板有几个 frontmatter 字段，HTML 就要有几个对应 <meta> / <link>，禁止因为「HTML 里看不见」就删字段。

字段review.htmlupdate-XXX-review.html机器可读人可读说明
标题必填必填rk:title / <title>h1功能名称-审查报告 / 功能名称-更新XXX-审查报告
类型必填必填rk:type类型固定 review
Spec 目录必填必填rk:spec-dirSpec含分类目录
角色必填必填rk:role角色固定 spec-reviewer
更新编号—必填rk:update-number更新编号与 update 文档一致
分类必填必填rk:category分类继承 writer/plan.html
状态必填必填rk:status状态未确认 / 已确认 / 已归档
审查结果必填必填rk:result审查结果通过 / 需修复 / 严重不符，与结论块 is-pass|is-fail 一致
严格程度必填必填rk:strictness严格程度严格（默认）/ 宽松（用户指定）
创建日期必填必填rk:created创建YYYY-MM-DD
更新日期必填必填rk:updated修订（括号内）最近一次修订日期

标签必填必填rk:tags不必显示逗号分隔，至少含 spec 与 review

修订规范

修改已确认的审查报告时永不静默改写：修订号 +1（同步 rk:revision 与 rk:updated）、修订历史表追加一行、正文用 <del class="rk-del" data-rev="N"> / <ins class="rk-ins" data-rev="N"> 标记行内改动， <p class="rk-removed|rk-added" data-rev="N"> 标记整段增删。完整规范见 html-report skill。

修订历史保持 5 列不变。源于实质取舍的修订，「原因」列引用运行账本 Decision Log 编号（如 按 D-005（本 Spec 采用宽松模式））；纯笔误、措辞、补充说明直接写清原因，不编造决策编号；决策过程正文留在账本，不复制进报告。

撰写要点

  • 审查结果用 Callout 分组：rk-cal ok 已完成、rk-cal risk 未完成/严重不符、rk-cal warn 不符项与需关注风险。
  • 结论块 rk-verdict is-pass|is-fail 与 rk:result 保持一致，一句话说清能否归档。
  • 每个检查项必须同时给出 Spec 位置与代码位置，代码位置一律 <span class="rk-ref">src/x.ts:88</span>。
  • 问题按高/中/低优先级分类，写进问题清单表；发现需升级的问题时同步登记运行账本「问题闭环记录」。
  • 双向关联：本报告 rk-links 加一条时，对侧报告 rk-backlinks 补一条；对侧尚未产出先标注「（待创建）」，等产出后补齐。
  • 禁止 <style>、行内 style=、外部 CDN；更新审查编号递增时同步替换文件名与全部链接。
