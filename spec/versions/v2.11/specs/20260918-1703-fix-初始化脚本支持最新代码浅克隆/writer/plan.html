设计目标与优化范围

解决初始化脚本 init-ai-workflow.sh、init-ai-workflow.ps1 在执行 git clone 时拉取仓库全量提交历史导致的下载耗时与冗余空间占用问题。通过引入 --depth=1 浅克隆参数，确保下游目标项目仅拉取最新代码镜像，并经严密测试验证其对既有 git pull --ff-only 增量更新逻辑的无缝兼容性；同时同步更新 README.md 与 spec-init/SKILL.md 中手动安装命令口径。

1. 现状痛点与根因分析

  1. 全量克隆的历史包袱：当前 scripts/init-ai-workflow.sh (第 46 行) 与 scripts/init-ai-workflow.ps1 (第 74 行) 均使用裸 git clone "$SKILLS_REPO_URL" .agents/skills。下游项目使用该脚本仅作为 Skills 规范运行时依赖，并不需要回溯或提交历史提交，全量拉取带来额外的网络传输带宽消耗与磁盘体积浪费。
  2. 手动文档与脚本口径不一致：README.md 第 55、66 行与 spec-init/SKILL.md 第 223 行指引的手动克隆命令同样为全量 git clone，缺乏 --depth=1 最佳实践指导。
  3. 浅克隆后续更新的兼容性确认：脚本内置了 git -C .agents/skills pull --ff-only 的增量更新逻辑。必须在方案中确认现代 Git（1.9+）在 --depth=1 单分支浅克隆状态下执行 fast-forward pull 的行为与对象树扩展能力，确保未来用户在执行增量更新时不会失败或中断。

2. 详细改造方案

2.1 双端初始化脚本更新

  • Bash 脚本 (scripts/init-ai-workflow.sh)： 
    # 原代码
git clone "$SKILLS_REPO_URL" .agents/skills

# 修改为
git clone --depth=1 "$SKILLS_REPO_URL" .agents/skills
  • PowerShell 脚本 (scripts/init-ai-workflow.ps1)： 
    # 原代码
git clone $SkillsRepoUrl ".agents\skills"

# 修改为
git clone --depth=1 $SkillsRepoUrl ".agents\skills"

2.2 分发与安装文档同步

  • README.md：Linux/macOS 与 Windows 原生 PowerShell 手动安装章节中的 git clone https://github.com/HHU3637kr/skills.git ... 命令均追加 --depth=1。
  • spec-init/SKILL.md：手动安装命令代码块中的 git clone https://github.com/HHU3637kr/skills.git .agents/skills 同步追加 --depth=1。

3. 验证与测试设计（测试先行与双向验证）

  1. 反向复现 (RED)： 验证无 --depth=1 时的 clone 会包含多条历史提交记录（commit count > 1），证实原脚本拉取了全量历史。
  2. 功能验证 (GREEN)： 修改脚本后，在隔离测试环境中执行克隆，验证 .agents/skills 的 commit 深度严格为 1（git rev-list --count HEAD == 1），且 .git/shallow 标记文件存在。
  3. 增量更新兼容性验证 (Regression Proof)： 模拟远端产生新提交场景，在浅克隆出的目录中执行 git -C .agents/skills pull --ff-only，验证：
    • 增量 pull 成功退出（退出码 0）；
    • 最新提交的代码正确合入工作区；
    • 脚本中的更新分支分支逻辑无任何报错。
