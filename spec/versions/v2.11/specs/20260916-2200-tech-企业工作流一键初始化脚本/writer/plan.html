设计目标与核心架构

面向 Linux、macOS 与 Windows 原生终端提供一套通用的项目一键初始化脚本（scripts/init-ai-workflow.sh 与 scripts/init-ai-workflow.ps1）。攻克 Windows 下符号链接默认提权限制（引入 NTFS Junction 免提权目录联接技术），实现环境检测、Git 仓库检测、Skills 规范源同步、企业治理规则落地、薄入口生成、三级架构骨架搭建与 AWR 运行时挂载的全流程自动化与幂等执行。

1. 现状痛点与核心挑战

  1. 冷启动摩擦大：新项目从零配置需要依次进行 clone、软链接、建目录、写模板、加 ignore 等多项手工操作，易漏易错。
  2. Windows 原生权限壁垒：Windows 普通用户运行 New-Item -ItemType SymbolicLink 会被系统拒绝，提示权限不足；Git Bash 下默认 ln -s 会降级为深拷贝整目录，破坏了单版本源的更新机制。
  3. 规范资产需要统一收敛：脚本不能只停留在某个业务工程中，必须沉淀在标准规范库 HHU3637kr/skills 的 scripts/ 目录中，随规范源版本演进。

2. 详细技术实现方案

2.1 核心执行流水线

  1. 依赖与环境检测：检查 git，探测 awr。若无 awr 输出友好指引，不阻断基础设施搭建。
  2. Git 状态保障：未初始化时自动执行 git init -b dev，符合 R&K Flow 规范。
  3. Skills 规范源挂载：拉取至 .agents/skills；若已存在则执行安全 git pull --ff-only。
  4. 跨平台免提权目录重定向：
    • Linux / macOS：执行 ln -sfn ../.agents/skills .omp/skills 与 ln -sfn .agents/skills/html-report html-report。
    • Windows Git Bash：探测 MSYS/MINGW 环境，调用 cmd.exe /c mklink /J 建立 NTFS Junction。
    • Windows 原生 PowerShell：使用 New-Item -ItemType Junction 创建 NTFS 目录联接，实现普通用户零提权即时可用。
  5. 企业治理规约固化：从 .agents/skills/.agents/rules/ 复制到项目级 .agents/rules/。
  6. 标准薄入口生成：按模板注入项目名，生成 .omp/AGENTS.md。
  7. 三级架构与经验知识库骨架：创建 spec/versions/，生成 spec/context/experience/index.md 与 spec/context/knowledge/index.md。
  8. AWR 状态机配置：生成标准 GOALS.md、work-ledger.yaml 与 .awr/project.toml，执行 awr init 和 awr source reindex。
  9. .gitignore 规则收敛：幂等追加运行时状态文件与软链接过滤项。

3. 验收标准与测试方案

  • Linux 环境测试：在 /tmp 创建临时空白目录，执行 init-ai-workflow.sh，校验目录树、软链接与 AWR 状态。
  • Windows 环境实测：在宿主机真实 NTFS 临时空间执行 init-ai-workflow.ps1，检验 LinkType 属性确为 Junction。
  • 幂等性校验：在同一目录原地二次执行，无报错且能安全刷新。
