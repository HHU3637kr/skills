1. 概述

1.1 背景

在沙箱实测与官方 v0.5.0 源码深度调研中，发现规范库存在核心契约脱节：spec-test/SKILL.md 误导用户将 HTML 报告传给 prepare-completion 导致 InvalidInput；.agents/rules/awr-integration.md 缺失了任务完工阶段真正的 work complete 机器核验协议与 40 位 SHA 约束，导致任务停留在声明完成态，AWR 报 completion_not_checked 缺口。

1.2 目标

  1. 纠正 spec-test/SKILL.md 中 prepare-completion 参数与产物指引，确立 HTML 与 JSON 双轨制。
  2. 在 .agents/rules/awr-integration.md 中建立完整的 AWR 完工机器核验协议（evidence add → prepare-completion → work complete → session end）。
  3. 在 spec-end/SKILL.md 补充通过 work complete 闭环机器核验的操作指引。
  4. 在 spec-execute/references/tdd-discipline.md 补全 RED 阶段必须执行真实断言（避免仅依赖缺失命令导致全部走 SKIP 分支）的纪律要求。
  5. 按版本范围变更规约同步修订 spec/versions/v2.11/plan.html 版本大盘。
  6. 在 /tmp 隔离沙箱中执行契约端到端全流程验证与 v2.11 既有 Spec 联合回归重测。

1.3 范围

包含：上述文档/规则的契约更新、v2.11 大盘同步、RED 测试先行脚本建设，以及在隔离沙箱中进行的全流程实测与联合回归。

不包含：修改 AWR 二进制代码；保持 scripts/rk-awr-checkpoint.{sh,ps1} 既有参数体系不变（当前会话与租约管理完全稳定，完工以直接调用 awr 命令闭环，避免引入计划外变更）。

2. 需求分析与设计方案

2.1 数据结构与契约规范

1. 机器完成报告结构（completion.report.v1）

interface CompletionReportV1 {
  version: 1;                     // 必须为整数 1
  work_item: string;              // 目标工作项 ID，如 "SPEC-RKGREET-001"
  source_sha: string;             // 40 位完整 Git commit SHA
  command: string;                // 验证命令，如 "bash tests/rkgreet.test.sh"
  scope: string[];                // 字符串数组，如 ["acceptance"]
  verified_at: number;            // 毫秒时间戳整数
  checks: Array<{
    name: string;                 // 用例名称，如 "TC-001"
    passed: boolean;              // 是否通过
    details: string;              // 验证明细
    criteria: string[];           // 必须与台账 acceptance 原文逐字一致
  }>;
}

2. 完工输入映射结构（work complete --input）

interface WorkCompleteInputV1 {
  version: 1;                     // 必须为整数 1
  source_sha: string;             // 40 位完整 Git commit SHA
  acceptance: Array<{
    criterion: string;            // 与台账 acceptance 原文逐字一致
    evidence: string[];           // 绑定的证据 external_key，如 ["SPEC-ID/evidence/test-run-001"]
  }>;
}

文件修改区块修改要点
