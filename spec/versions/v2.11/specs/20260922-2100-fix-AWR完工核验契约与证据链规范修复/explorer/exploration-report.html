1. 现状痛点与缺陷根因

1.1 spec-test/SKILL.md 完工指引断裂

在 spec-test/SKILL.md:555 中，文档指示：

awr work prepare-completion --report <REPORT-PATH> --evidence-key <KEY> --source-sha <SHA> <SPEC-ID>

由于上文全在描述 tester/test-report.html，执行者误将 HTML 文件传入 --report，直接触发 AWR 的 completion.report.v1 schema 校验拒绝：

{"code":"InvalidInput","message":"invalid source: invalid completion report schema"}

1.2 .agents/rules/awr-integration.md 缺少 work complete 协议

规则文件只定义了：

  1. session start --claim
  2. work prepare --session
  3. session checkpoint
  4. session resume
  5. session end

完全缺失了由 AWR 官方提供的从 prepare-completion 到 work complete 的机器核验步骤，导致任务在 AWR 数据库中要么仅停留在源声明 completed（常驻 completion_not_checked 缺口），要么无法在释放租约前将任务推进为真正的机器核验完工。

1.3 40 位完整 SHA 强约束未做文档化

实测执行 --source-sha $(git rev-parse --short HEAD) 时，AWR 强拦截：--source-sha requires a full source SHA，必须传 40 位哈希。

2. 官方源码调研证据（AWR v0.5.0）

查阅 github.com/originoneai/awr 标签 v0.5.0 的测试夹具 examples/host-app/test_workflow.py:52-62：

2.1 prepare-completion 标准报告 JSON (completion.report.v1)

report = {
    "version": 1,                               # 整数 1
    "work_item": "SPEC-ID",                     # 工作项键
    "source_sha": "40位完整Git哈希",             # 必须40位
    "command": "测试执行命令",
    "scope": ["SPEC-ID"],                       # 字符串数组
    "verified_at": 1790000000000,               # 毫秒时间戳整数
    "checks": [
        {
            "name": "TC-001",
            "passed": True,
            "details": "测试断言详情",
            "criteria": ["台账中 acceptance 的原文"]  # 必须与台账逐字完全一致
        }
    ]
}

2.2 work complete 标准 input JSON

input = {
    "version": 1,
    "source_sha": "40位完整Git哈希",
    "acceptance": [
        {
            "criterion": "台账中 acceptance 的原文",
            "evidence": ["EVIDENCE_EXTERNAL_KEY"]
        }
    ]
}

3. 沙箱实测验证结论

在 /tmp/rksim 隔离沙箱中，使用上述官方三字段 input 执行：

awr work complete --session "$SESS" --reason "验收通过" --input /tmp/official-complete.json --expected-revision "$REV" SPEC-RKGREET-001 --json

执行结果：返回退出码 0，事件 work.completed 成功上链，AWR 自动在 work-ledger.yaml 注入机器核验标识 verification: {evidence_level: locally_verified}！随后执行 session end，awr doctor 达到 0 findings 的无瑕闭环。

4. 对设计与测试的建议

  • 双轨制定位：明确 HTML 报告（人读 + Gutter批注 + 修订追溯）与 JSON 报告（AWR 机器核验）双轨并存，不可偏废。
  • 检查点脚本封装：评估在 scripts/rk-awr-checkpoint.sh 中增加 --complete 选项，由脚本自动组装三字段 JSON 调 awr work complete，彻底解脱手动拼接 JSON 的负担。
