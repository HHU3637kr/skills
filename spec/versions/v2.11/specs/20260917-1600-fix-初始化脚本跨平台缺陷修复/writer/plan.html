设计目标与修复范围

依据在 Linux ext4 与 Windows NTFS 真实双端沙箱中暴露的实际问题，对 scripts/init-ai-workflow.sh 与 scripts/init-ai-workflow.ps1 进行彻底的健壮性修复：实现目标路径自愈预建、消除 AWR 0.4.0 状态机悬空边报错、建立 Windows 普通目录安全备份与规则防覆写机制、并全面统一为 UTF-8 无 BOM 输出及读取防退化。

1. 缺陷清单与根因分析

  1. 目标路径未预建导致解析崩溃：若目标目录未物理创建，Bash 的 cd "$TARGET_DIR" 与 PowerShell 的 Resolve-Path $TargetDir 均会直接抛出致命错误中断执行。
  2. AWR 0.4.0 状态机悬空边异常 (dangling_edge)：在 work-ledger.yaml 中指定 goal: intake-goal 会使 AWR 在无对应显式实体注册时报告 [error] dangling_edge ... target goal:intake-goal is missing or retired，导致 awr doctor 校验失败。去除显式 goal 绑定符合标准 intake 单独组织任务定义。
  3. Windows 下普通物理目录被硬删除 (破坏性行为)：New-JunctionSafely 遇到普通物理目录直接调用 Remove-Item -Recurse -Force，导致用户既有数据瞬间丢失。
  4. Windows 下用户定制规则被强制覆盖：PS1 脚本使用 Copy-Item ... -Force，会无条件覆盖项目特化规则（如已被修改的 spec-workflow.md），而 Linux 端采用 cp -rn 则无此问题。
  5. Windows PowerShell 5.1 编码与 BOM 退化陷阱：使用无 BOM UTF-8 写出 .gitignore 后，若在下一次运行时使用默认 Get-Content，PS 5.1 会以系统默认 ANSI 代码页（如 CP936）读取，造成非 ASCII/中文注释内容乱码并写回，破坏文件。

2. 详细修复技术方案

2.1 目标路径前置自愈

  • scripts/init-ai-workflow.sh：在第 10 行执行 mkdir -p "$TARGET_DIR"，再执行 cd "$TARGET_DIR" && pwd。
  • scripts/init-ai-workflow.ps1：在第 28 行前执行 if (-not (Test-Path $TargetDir)) { New-Item -ItemType Directory -Force -Path $TargetDir | Out-Null }。

2.2 AWR 0.4.0 模板兼容修补

  • 修改 scripts/init-ai-workflow.sh 和 .ps1 中的 work-ledger.yaml 生成模板，移除 goal: intake-goal。
  • 实测保证 awr doctor 返回 Findings: 0，Database intact: true。

2.3 目录安全重命名与防覆盖保护

  • Windows Junction 安全重命名：在 New-JunctionSafely 中，遇到非 ReparsePoint 目录时，采用 Move-Item -Path $Path -Destination "$Path.bak-..." 备份，并输出黄色告警。
  • Linux 软链接防护：若 .omp/skills 或 html-report 为普通物理目录，同样备份至 .bak，防止 ln -sfn 产生嵌套。
  • Windows 规则无覆盖同步：遍历源规则目录，仅当目标规则文件不存在时才执行复制，完整对齐 cp -rn 语义。

2.4 UTF-8 无 BOM 读写闭环防退化

  • 在 PowerShell 脚本开头声明 $Utf8NoBom = New-Object System.Text.UTF8Encoding($false)。
  • 写出 .omp/AGENTS.md、spec/...、GOALS.md、work-ledger.yaml 与 .gitignore 时统一传入 $Utf8NoBom。
  • 读取 .gitignore 时显式使用 Get-Content $gitIgnorePath -Encoding UTF8，保证即使多次运行且包含中文注释，也不会发生 ANSI 二次污染。

3. 验收标准

  1. Ubuntu 沙箱运行后，awr doctor 检查 Findings: 0。
  2. Windows 沙箱运行后，哨兵普通目录成功备份为 .bak，哨兵文件不丢失；用户定制规则哈希不变。
  3. 目标路径在不存在时传入两端脚本，均能平滑自愈并成功初始化。
  4. Windows 原生 Node.js 解析生成的文件，首字节无 BOM (0xEF 0xBB 0xBF)，且中文内容完整。
  5. 在 .gitignore 中预置中文注释与特殊条目，连续运行 2 次 PS1，文件字节哈希与中文内容严格保持无损。
