设计目标与核心方案

彻底消除 scripts/init-ai-workflow.{sh,ps1} 中对本地 OMP 环境的硬编码强绑定偏置。将 AGENTS.md 还原至业务项目根目录，作为跨 Agent 统一公共入口；在目标项目补齐 .agents/roles/ 7 大中立角色权威定义；解除 OMP 冗余的 .omp/skills 软链接并支持 --runtime <none|omp|claude|codex> 参数化按需适配；同步对齐 spec-init/SKILL.md、README.md 与 CODEMAP.md 规约文档。

1. 现状痛点与缺陷根因分析

  1. 入口锁死在私有目录：当前脚本直接将入口生成至 .omp/AGENTS.md，导致业务项目根目录缺失统一的 ./AGENTS.md。团队中若有成员使用 Claude Code、Codex、Cursor，或在 CI/CD 中运行 Headless Agent，均无法读取规范入口。
  2. 中立角色定义权威源丢失：脚本全程没有 mkdir -p .agents/roles，未生成 spec-explorer.md 等 7 个中立角色定义。而 CODEMAP 与 spec-start 明确以 .agents/roles/ 作为角色定义的跨 CLI 唯一权威源。
  3. 私有软链接冗余与无脑绑定：脚本无条件创建 .omp/skills 软链接。实际上 OMP 客户端原生即可从 .agents/skills/ 发现技能，该链接纯属冗余；且脚本缺少对 Claude Code（需 .claude/skills）与 Codex（需 .codex/skills）的按需支持。
  4. 文档规范与脚本行为不一致：spec-init/SKILL.md 步骤 4.2 未说明 OMP 的原生发现能力，遗留了历史软链接描述，且未对 .gitignore 隔离本地私有运行时给出明确边界。

2. 详细改造方案

2.1 脚手架双端脚本重构 (scripts/init-ai-workflow.{sh,ps1})

  • 参数化运行时支持：
    • 新增 --runtime (Bash) / -Runtime (PowerShell) 参数，可选值：none (默认)、omp、claude、codex。
    • 默认 none 时保持纯中立：只装配业务规范公共资产，不创建任何私有隐藏目录。
  • 根目录 AGENTS.md 落地：
    • 彻底废除 .omp/AGENTS.md 生成逻辑。
    • 文件直接写入目标根目录 $TARGET_DIR/AGENTS.md，显式引入 @import .agents/rules/ 与 @import .agents/skills/，声明三级架构与角色目录路由。
  • 落地 .agents/roles/ 中立角色定义：
    • 创建 .agents/roles/ 目录。
    • 从 .agents/skills/.agents/roles/（若规范库已自带）或预置规范中无损复制 7 个角色定义：spec-explorer.md、spec-writer.md、spec-tester.md、spec-executor.md、spec-debugger.md、spec-reviewer.md、spec-ender.md。
  • 差异化按需适配矩阵：
    • --runtime omp：创建 .omp/agents/，生成 7 个薄适配 Markdown（首行读取中立 roles），绝不创建 .omp/skills 软链接。
    • --runtime claude：创建 .claude/agents/ 并建立 .claude/skills -> ../.agents/skills 软链接。
    • --runtime codex：创建 .codex/agents/、.codex/config.toml 并建立 .codex/skills -> ../.agents/skills 软链接。
  • .gitignore 收敛与隔离： 追加 .omp/、.claude/、.codex/ 至忽略规则，确保个人客户端外挂不污染团队业务 Git 仓库。

2.2 规范与指引文档同步

  • spec-init/SKILL.md：
    • 步骤 3：明确 AGENTS.md 位于项目根目录，是唯一中立入口。
    • 步骤 4.2：澄清 OMP 原生发现 .agents/skills/，无需建立 .omp/skills 软链接；保留 Claude/Codex 的按需软链接说明。
    • 步骤 4.3：强调 .agents/roles/ 为团队权威源，运行时适配为开发者本地私有外挂。
  • README.md 与 CODEMAP.md： 更新初始化产物拓扑图与各 Coding Agent 集成说明，修正目录层次。

3. 关键决策与边界 (Key Decisions)

架构决策：业务公共资产与客户端本地适配严格物理隔离

结论：业务代码库仅持有 AGENTS.md、.agents/rules/、.agents/roles/、spec/ 与 html-report/。所有 .<runtime>/ 目录均被视为开发者本地环境外挂，默认忽略，彻底保障项目跨平台、跨 IDE、跨 Agent 的通用性与整洁性。
