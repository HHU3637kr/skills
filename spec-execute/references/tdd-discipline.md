# TDD 执行细则

`spec-execute` 运行契约的「参考」行路由到本文件：任务涉及代码改动 → 开工前必读。

## 铁律

没有失败的测试，不写实现代码。

例外只有一种：改动完全不产生可观察行为（纯格式化、纯注释）。"这个太简单了"不是例外。

## RED：四个确认

写完测试、跑之前，先想清楚它应该怎么失败。跑完后确认四件事：

1. **测试确实失败了。** 没跑就不算——通过想象确认的 RED 不是 RED。
2. **失败原因是功能缺失，不是笔误。** 导入错误、拼写错误、语法错误导致的失败是假 RED。读失败信息，确认它抱怨的是"这个行为不存在"。
3. **断言的期望值是手工推导出来的。** 不是把当前实际输出粘进断言里。先自己算出正确答案应该是什么，再写进断言。
4. **断言逻辑确实被完整执行，杜绝全 SKIP 假红。** 对脚本或 CLI 工具，如果被测目标完全不存在导致测试套件全走入 `SKIP` 分支（虽然整体可能因通过数为 0 而退出码非零），具体的行为断言逻辑并未被触发。在运行 RED 阶段前，被测目标应先具备最小空桩（stub，如仅含 shebang 与 `exit 0` 的空程序），使测试套件真实运行并产生确凿的断言级 `FAIL`。

第 3 点与第 4 点最容易被忽略。把实际输出复制成期望值会得到永远发现不了 bug 的测试，而依赖文件缺失全跳过则可能掩盖断言代码本身的语法缺陷。
## GREEN：只写让测试通过的代码

不顺手加相邻功能，不预留扩展点。多写的每一行都没有测试覆盖。

## 提交前的门函数

对每个新写的测试，回答一句话：

> **什么改动会让这个测试失败？**

答不出具体的改动，这个测试就是无效的，删掉或重写。

答案必须是具体行为，不能是"代码坏了"这类空话。合格的答案例如：「把 `retryCount` 默认值从 3 改成 0」「把边界判断从 `<=` 改成 `<`」。

## 假测试的典型形态

**断言源文本。** 检查源文件里有没有某个字符串，而不是检查行为。

```
# 假测试：改个措辞就红，行为坏了却是绿
assert "retry" in open("client.py").read()

# 真测试：断言可观察行为
assert client.call(flaky_endpoint).attempts == 3
```

本仓库尤其容易犯这条——R&K 改的大多是 Skill 文档、规则文件与 HTML 报告，"grep 到这行字就算过"是最省事也最没用的写法。文档类改动的正确验证方式见下节。

**恒真断言。** `assert result is not None`、`assert len(x) >= 0`、`assert True`。

**测试自己的 mock。** 断言只碰到了 mock 的返回值，真实代码路径一行没走。

**跟着实现改期望值。** 实现输出变了就把断言改成新输出。这时测试已经不是规格，只是实现的影子。

## mock 四规则

1. 只 mock 进程外的东西（网络、时钟、文件系统、随机源）。
2. 不 mock 被测对象本身，也不 mock 同一模块内的协作者。
3. mock 的返回值必须是真实接口真的会返回的形状——包括错误形状。
4. 每个 mock 至少配一个不 mock 的测试覆盖同一路径，否则接口漂移时没人发现。

## 非代码改动怎么办

TDD 不是对所有产物都有等价形式。按三类处理，不要伪造失败测试：

| 改动类型 | 验证方式 |
|---|---|
| 脚本、工具、可执行物 | 跑它，断言产物或退出码 |
| 面向 Agent 的文档（Skill、规则） | 由消费方行为验证：先在无该规则时跑基线场景、记录 Agent 的选择，加规则后跑同一场景、比较选择是否改变。那次基线违规就是 RED |
| 面向人的散文（README 叙述、注释） | 不配测试，人读即可 |

第二类的构造方法见 `skill-creator` 的压力测试章节。

## 证据落盘

`executor/artifacts/` 下的内容必须由测试运行自身产出，重定向或测试框架报告都可以，但不能手写、补写、回填。

必须能看出：跑了什么命令、退出码是多少、失败时的断言原文是什么。缺退出码或缺时间戳的"证据"视为无效。

因此每份证据日志的头部必须包含三行（框架报告自带命令/时间戳/结果汇总的，可用其原生输出，但三要素必须齐）：

```text
=== TDD RED Run ===
Command: python3 -m unittest discover -s . -p "test_*.py" -v
Timestamp: 2026-09-22T23:13:52+08:00
…（测试原始输出，失败时保留断言原文与 diff）…
Exit code: 1
```

`summary.html` 引用的命令与结论必须与证据文件一致，不一致以证据文件为准。spec-end 的「报告契约与证据机检」门禁会机械校验 tester/executor 证据日志的三要素，缺一即禁止归档。
